# AutoMorph & Obtainium Release Integration Specification

**Date:** 2026-10-31  
**Status:** Approved  
**Author:** Antigravity & User  

---

## 1. Overview & Goal

The goal of this specification is to provide seamless, one-click Obtainium tracking and direct installation for all patched APKs generated by AutoMorph, while eliminating version mismatches, package ID collisions, and missing links across GitHub releases and the AutoMorph web portal.

---

## 2. Architecture & Link Structure

### 2.1 Release Notes Layout (GitHub Releases)
Every GitHub release created by the GitHub Actions builder (`automorph-cloud-builder.yaml`)—including both the primary unified batch release (`build-YYYYMMDD-HHMMSS`, marked `--latest`) and the individual per-app rolling releases (`app-<package>`)—must contain:

1. **AutoMorph Web Dashboard Link:**
   - Link: `https://automorph.w161112218.workers.dev`
   - Repository Context: `wiwek13/AutoMorph`
2. **Per-App Summary:**
   - App Name and Display Version (e.g. `Truecaller` - `v26.41.5`)
   - Package ID (e.g. `com.truecaller`)
   - Direct APK Download link
   - Direct 1-Click Obtainium link: `👉 [📲 Add to Obtainium](<redirect_url>)`
3. **Obtainium Direct Deep-Link Payload:**
   - Standardized scheme: `obtainium://app/<json-payload>`
   - Web Redirect Bridge: `https://apps.obtainium.imranr.dev/redirect?r=<encoded-scheme>`
   - Serialized Payload:
     ```json
     {
       "id": "com.truecaller",
       "url": "https://github.com/wiwek13/AutoMorph",
       "author": "wiwek13",
       "name": "Truecaller",
       "additionalSettings": "{\"fallbackToOlderReleases\": true, \"filterReleaseTitlesByRegEx\": \"Truecaller\", \"apkFilterRegEx\": \"truecaller\"}"
     }
     ```

### 2.2 AutoMorph Web Portal (`worker/router.ts`)
1. In the `/api/files` endpoint and Obtainium export (`/api/obtainium/export`):
   - Ensure `url` points to `https://github.com/wiwek13/AutoMorph`
   - Include direct `obtainium_url` and `obtainium_web_url` with the exact verified JSON payload.
   - Link back to GitHub releases directly from the file cards in the Web UI.

---

## 3. Implementation Scope & Files

1. `.github/workflows/automorph-cloud-builder.yaml`:
   - Update `$NOTES_FILE` generation in the `Create GitHub Release for Patched APKs` step to generate the 1-click Obtainium link for each APK and embed it in the batch release notes.
   - Include AutoMorph dashboard link (`https://automorph.w161112218.workers.dev`) and repository link in the release header.
   - Ensure the per-app release notes (`$PER_APP_NOTES`) have the same structure.
2. `worker/router.ts`:
   - Keep `/api/files` and `/api/obtainium/export` in sync with the clean Obtainium settings.
3. Automated Verification:
   - Commit and push to `main`.
   - Trigger a live workflow run for `com.truecaller`.
   - Verify the generated release notes on GitHub and test the Obtainium link.

---

## 4. Verification & Testing Criteria
- [x] Release notes on GitHub render clean markdown with clickable direct download and Obtainium buttons.
- [x] No raw backslash escaping errors when Obtainium imports the payload.
- [x] Obtainium detects package `com.truecaller` and version `26.41.5` without "Could not find a suitable release".
